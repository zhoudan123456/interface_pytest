# 一对多匹配问题修复说明

**问题**: 算法输出（粗粒度）vs 人工标注（细粒度）的匹配问题

**更新时间**: 2026-01-30 15:10

---

## 🔴 原问题

### 场景

```
算法输出 (粗粒度):
ID:4424 = "2.应答人资格要求
          2.1独立法人要求...
          2.2财务要求...
          2.3人员要求...
          ...
          2.8不得存在的情形..."

人工标注 (细粒度):
CP-001: 主体资格证明文件（对应2.1）
CP-002: 财务要求（对应2.2）
CP-003: 人员要求（对应2.3）
...
CP-008: 不得存在的情形（对应2.8）
```

### 旧代码问题

```python
for algo_checkpoint in category_nodes:
    if algo_id in matched_algo_ids:
        continue  # ❌ 跳过已匹配的

    if result['is_contained']:
        matched_algo_ids.add(algo_id)  # ❌ 标记为已匹配
        break
```

**导致的结果**：
```
CP-001 → 检查 ID:4424 → ✓ 匹配 → ID:4424标记为"已匹配"
CP-002 → 检查 ID:4424 → ✗ 跳过（因为已匹配）❌
CP-003 → 检查 ID:4424 → ✗ 跳过（因为已匹配）❌
...
CP-008 → 检查 ID:4424 → ✗ 跳过（因为已匹配）❌

结果: 遗漏率 87.5% (7/8)
```

## ✅ 修复方案

### 核心思路

**允许多对一匹配**：多个检查点可以匹配到同一个算法节点

### 修复后的代码

```python
for algo_checkpoint in category_nodes:
    algo_id = algo_checkpoint['id']
    algo_text = algo_checkpoint['value']

    # 调用智谱AI进行判断
    result = self.check_if_contained(checkpoint_text, algo_text, algo_id)

    if result['is_contained']:
        is_matched = True
        best_match = {...}
        # 记录匹配关系（用于统计误报，但不阻止其他检查点使用）
        matched_algo_ids.add(algo_id)  # ✅ 仅用于统计，不用于过滤
        break
```

**关键修改**：
- ❌ 移除了：`if algo_id in matched_algo_ids: continue`
- ✅ 保留了：`matched_algo_ids.add(algo_id)`（用于误报检测）

### 新的执行流程

```
CP-001 → 检查 ID:4424 → ✓ 匹配 → matched_algo_ids.add(4424)
CP-002 → 检查 ID:4424 → ✓ 匹配 → matched_algo_ids.add(4424)（重复添加无影响）
CP-003 → 检查 ID:4424 → ✓ 匹配 → matched_algo_ids.add(4424)
...
CP-008 → 检查 ID:4424 → ✓ 匹配 → matched_algo_ids.add(4424)

结果: 所有8个检查点都匹配成功！
```

## 📊 误报检测逻辑

### 为什么保留 `matched_algo_ids`？

`matched_algo_ids` 用于检测误报（False Positives）：

```python
# 找出误报（算法输出中未被任何检查点匹配的节点）
for algo_checkpoint in all_algo_nodes:
    algo_id = algo_checkpoint['id']
    if algo_id not in matched_algo_ids:  # ← 这里仍然有用
        fp.append(...)  # 未被匹配的算法节点 = 误报
```

### 逻辑说明

```
算法节点 ID:4424 被 CP-001 匹配
→ matched_algo_ids = {4424}

算法节点 ID:4424 又被 CP-002 匹配
→ matched_algo_ids = {4424}（无变化，集合自动去重）

最终检查：
→ ID:4424 in matched_algo_ids ✓
→ ID:4424 不被认为是误报 ✓
```

## 🎯 匹配模式总结

### 支持的匹配模式

修复后，支持两种匹配模式：

#### 1. 一对一匹配（常见）

```
算法节点 A → 匹配 → 检查点 X
算法节点 B → 匹配 → 检查点 Y
算法节点 C → 未匹配 → 误报
```

#### 2. 多对一匹配（粗粒度vs细粒度）✅

```

算法节点 ID:4424 → 匹配 → CP-002 (2.2)
算法节点 ID:4424 → 匹配 → CP-003 (2.3)
...
算法节点 ID:4424 → 匹配 → CP-008 (2.8)

ID:4424 被多个检查点匹配，但不认为是误报
```

## ✅ 总结

### 问题根源

旧代码假设**一对一匹配**（一个算法节点对应一个检查点），但实际情况是**多对一匹配**（一个粗粒度算法节点包含多个细粒度检查点）。

### 解决方案

移除"跳过已匹配节点"的限制，允许多个检查点匹配到同一个算法节点。

### 适用场景

这个修复特别适用于：
- ✅ 算法输出粒度粗（如"资格要求"大段文本）
- ✅ 人工标注粒度细（如2.1、2.2、2.3分别标注）
- ✅ 一个算法节点包含多个检查点
