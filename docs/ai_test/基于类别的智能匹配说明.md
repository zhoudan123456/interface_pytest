## 🎯 核心改进

### 问题背景

**您的发现**：
> "应该是根据表格中的类别，在json中的资格下进行查找"

**原问题**：
```
算法输出JSON结构:
├── 资格评审
│   └── 资格要求
│       └── ID: 4424 (包含2.1-2.8所有内容的长文本)
├── 响应性评审
│   └── 格式要求
│       └── ID: 1001
└── 综合评审
    └── 技术方案
        └── ID: 2001

Excel标注:
- CP-001: "主体资格证明文件" (类别: 资格评审)
- CP-002: "财务要求" (类别: 资格评审)
- CP-003: "投标文件格式要求" (类别: 响应性评审)
```

**旧方案（盲目查找）**：
```
对 CP-001 → 遍历JSON所有节点 → 大量无效的LLM调用 ❌
对 CP-002 → 遍历JSON所有节点 → 大量无效的LLM调用 ❌
```

**新方案（基于类别）**：
```
对 CP-001 (类别: 资格评审) → 只在"资格评审"分支下查找 ✅
对 CP-002 (类别: 资格评审) → 只在"资格评审"分支下查找 ✅
对 CP-003 (类别: 响应性评审) → 只在"响应性评审"分支下查找 ✅
```

## 📊 工作原理

### 1. 构建类别映射

```python
def build_category_mapping(node_list, parent_category=""):
    """
    递归遍历JSON树，构建: {类别名称: [节点列表]}
    """
    category_map = {}

    for node in node_list:
        if node.get('id') is not None:  # 叶子节点（有ID的才是实际检查点）
            # 使用父级类别作为分类依据
            if parent_category not in category_map:
                category_map[parent_category] = []

            category_map[parent_category].append({
                'id': node['id'],
                'value': node['value'],
                'label': node['label']
            })

        # 递归处理子节点
        if node.get('children'):
            child_map = build_category_mapping(node['children'], ...)
            # 合并映射
            category_map.update(child_map)

    return category_map
```

### 2. 类别映射示例

```python
# 输入JSON结构
{
    "data": [
        {
            "label": "资格评审",  # ← 类别
            "children": [
                {
                    "id": 4424,     # ← 实际检查点
                    "value": "2.应答人资格要求..."
                }
            ]
        }
    ]
}

# 输出类别映射
{
    "资格评审": [
        {
            "id": 4424,
            "value": "2.应答人资格要求...",
            "parent_category": "资格评审"
        }
    ]
}
```

### 3. 匹配流程

```python
for checkpoint in annotation_data:
    category = checkpoint['类别']  # 从Excel读取: "资格评审"

    # 只获取该类别下的节点
    category_nodes = category_mapping.get(category, [])

    # 只对这些节点调用LLM判断
    for node in category_nodes:
        result = llm_check_if_contained(
            checkpoint['检查点文本'],
            node['value']
```

## 📈 性能对比

### 场景假设
- JSON总节点数: 100个
- 类别数: 5个
- 每个类别平均节点数: 20个
- 人工标注检查点: 10个

### 旧方案（盲目查找）

```
对每个检查点，遍历所有100个节点
LLM调用次数 = 10个检查点 × 100个节点 = 1000次 ❌
成本 = 1000次 × ¥0.0002/次 = ¥0.20
时间 = 1000次 × 0.5秒 = 500秒 ≈ 8.3分钟
```

### 新方案（基于类别）

```
对每个检查点，只遍历对应类别的20个节点
LLM调用次数 = 10个检查点 × 20个节点 = 200次 ✅
成本 = 200次 × ¥0.0002/次 = ¥0.04
时间 = 200次 × 0.5秒 = 100秒 ≈ 1.7分钟
```

### 提升

| 指标 | 旧方案 | 新方案 | 提升 |
|------|--------|--------|------|
| LLM调用次数 | 1000次 | 200次 | **5倍** |
| 成本 | ¥0.20 | ¥0.04 | **5倍** |
| 时间 | 8.3分钟 | 1.7分钟 | **5倍** |
| 准确性 | 可能误匹配 | 精确匹配 | **更高** |

## 📝 Excel类别字段要求

### 重要

Excel标注文件必须包含**类别**字段，且类别名称需要与JSON中的标签对应：

| 检查点ID | 检查点文本 | 类别 |
|----------|------------|------|
| CP-001 | 主体资格证明文件... | **资格评审** |
| CP-002 | 财务要求... | **资格评审** |
| CP-003 | 投标文件格式要求... | **响应性评审** |
| CP-004 | 技术方案评分... | **综合评审** |

### 类别对应关系

```
Excel中的"类别" ← 对应 → JSON中的父级标签

例如:
Excel: "资格评审" → JSON: {"label": "资格评审", "children": [...]}
```

### 1. 类别标准化

如果Excel中的类别名称与JSON中的标签不完全一致，可以建立映射表：

```python
category_mapping_rules = {
    "资格评审": ["资格评审", "资格要求", "资格审查"],

    "综合评审": ["综合评审", "技术评分", "商务评分"]
}
```

### 2. 模糊类别匹配

```python
from rapidfuzz import fuzz

def find_matching_category(excel_category, json_categories):
    """找到最匹配的JSON类别"""
    best_match = process.extractOne(
        excel_category,
        json_categories,
        scorer=fuzz.token_sort_ratio
    )
    if best_match[1] >= 85:  # 相似度阈值
        return best_match[0]
    return None
```

### 3. 缺失类别处理

如果某个检查点的类别在JSON中找不到，当前脚本会自动回退到全量搜索：

