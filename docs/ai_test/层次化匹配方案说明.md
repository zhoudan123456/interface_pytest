# 检查点层次化匹配方案

## 📋 问题背景

在实际验证中发现，**人工标注**和**算法输出**的检查点粒度可能不一致：

### 案例1：粗粒度 vs 细粒度

**算法输出**（粗粒度，一个段落包含多个要求）：
```
2.应答人资格要求
2.1本项目要求应答人必须为中国境内依法注册的独立法人或依法成立的其他组织。提供营业执照扫描件或其他有效证明文件。
2.2财务要求:应答人能开具增值税专用发票,且未处于被责令停业、财产被接管、冻结、破产状态。提供承诺书。
2.3人员要求:为本项目提供1个服务团队,不少于5名值班人员须具有中专及以上学历和高压电工证...
2.4业绩要求:应答人须提供2020年1月1日至本公告发布之日止(以合同或订单签订日期为准)类似机房维护或值守代维项目业绩...
2.5本项目不接受联合体应答。
2.6单位负责人为同一人或者存在控股、管理关系的不同单位,不得参加同一比选项目应答...
2.7未处于中国联通集团公司或江苏联通供应商黑名单禁入期内或预警期内...
2.8应答人不得存在下列情形之一:(1)为采购人不具有独立法人资格的附属机构(单位)...
```

**人工标注**（细粒度，拆分成8个独立检查点）：
- CP-001: 主体资格证明文件（对应2.1）
- CP-002: 财务要求（对应2.2）
- CP-003: 人员要求（对应2.3）
- CP-004: 业绩要求（对应2.4）
- CP-005: 联合体（对应2.5）
- CP-006: 控股、管理关系（对应2.6）
- CP-007: 黑名单核查（对应2.7）
- CP-008: 不得存在的情形（对应2.8）

### 问题

如果仅使用**文本相似度匹配**（如token_sort_ratio），由于文本长度和结构差异大，相似度会很低，导致所有检查点都被误判为"遗漏"。

但实际上，**算法已经识别了这些内容**，只是粒度不同！

---

## ✅ 解决方案：层次化匹配

### 匹配策略

采用**三种匹配模式**的组合：

```
层次化匹配
│
├── 1. 完全匹配（Exact Match）
│   ├── 条件：相似度 ≥ 85%
│   ├── 说明：文本基本一致，可能有细微差异
│   └── 示例：
│       人工: "总报价不超过项目(分包)预算金额或最高限价"
│       算法: "磋商报价：总报价不超过项目(分包)预算金额或最高限价"
│       相似度: 89.4% ✅
│
├── 2. 包含匹配 - 算法包含人工（Contained）
│   ├── 条件：人工文本 ∈ 算法文本 且 长度比 ≤ 0.8
│   ├── 说明：算法输出更粗粒度，包含人工标注的细粒度检查点
│   └── 示例：
│       人工: "主体资格证明文件：本项目要求应答人必须为中国境内依法注册的独立法人..."
│       算法: "2.应答人资格要求\n2.1本项目要求应答人必须为中国境内依法注册的独立法人...\n2.2财务要求..."
│       关系: 人工标注是算法输出的子集 ✅
│
└── 3. 包含匹配 - 人工包含算法（Contains）
    ├── 条件：算法文本 ∈ 人工文本
    ├── 说明：人工标注更粗粒度，算法输出是其子集（较少见）
    └── 示例：
        人工: "应答人须提供营业执照、资质证书、安全生产许可证"
        算法: "应答人须提供营业执照"
        关系: 算法输出是人工标注的子集 ✅
```

### 算法实现

```python
def match_checkpoints(threshold=0.85, use_containment=True):
    """层次化匹配检查点"""

    for gt_checkpoint in ground_truth:
        gt_text = gt_checkpoint['text']

        # 方法1: 高相似度匹配（完全一致）
        matches = process.extract(gt_text, algorithm_texts, scorer=fuzz.token_sort_ratio, limit=1)

        if matches[0][1] >= threshold * 100:
            # 完全匹配
            match_type = 'exact'
            is_matched = True

        # 方法2: 包含关系匹配
        elif use_containment:
            for algo_text in algorithm_texts:
                # 检查人工标注是否包含在算法输出中（粗→细）
                if gt_text in algo_text:
                    containment_ratio = len(gt_text) / len(algo_text)
                    if containment_ratio <= 0.8:  # 人工明显较短
                        match_type = 'contained'
                        is_matched = True
                        break

                # 检查算法输出是否包含在人工标注中（细→粗）
                elif algo_text in gt_text:
                    match_type = 'contains'
                    is_matched = True
                    break
```

## 📊 匹配结果分类

### 1. True Positive (TP) - 正确识别

分为三种子类型：

| 类型 | 代码 | 说明 | 示例场景 |
|------|------|------|----------|
| 完全匹配 | `exact` | 文本高度相似 | 人工和算法识别相同检查点 |
| 算法包含人工 | `contained` | 算法输出粒度更粗 | 算法输出整个段落，人工拆分标注 |
| 人工包含算法 | `contains` | 人工标注粒度更粗 | 人工标注整体要求，算法只识别部分 |

### 2. False Negative (FN) - 遗漏

**人工标注了，但算法没有识别**（任何匹配模式都不满足）

### 3. False Positive (FP) - 误报

**算法识别了，但人工没有标注**（可能是误报，也可能是人工遗漏）

## 💡 最佳实践

### 标注建议

1. **推荐粒度**：按照**独立要求**进行标注
   - ✅ 一个资格条件 = 一个检查点
   - ✅ 一个评分项 = 一个检查点
   - ❌ 不要把整个段落作为一个检查点

2. **包含关系处理**：
   - 如果算法输出整个段落，人工标注应该拆分
   - 验证工具会自动识别包含关系

3. **文本完整性**：
   - 人工标注时，尽量复制完整文本
   - 不要删减或改写原文

### 验证流程

1. **第一次运行**：使用层次化匹配（默认）
   ```bash
   python scripts/quick_verify.py annotations/标注.xlsx data/algorithm.json
   ```

2. **查看报告**：重点关注匹配类型
   - 如果大部分是"包含匹配"，说明粒度不一致
   - 如果大部分是"完全匹配"，说明粒度一致

3. **优化策略**：
   - 如果遗漏率高：检查是否为粒度问题，启用包含匹配
   - 如果误报率高：检查人工标注是否完整

## ⚠️ 注意事项

### 1. 包含匹配的局限

**风险**：可能产生误匹配

**示例**：
```
人工: "提供营业执照"
算法: "提供营业执照、资质证书、安全生产许可证"
```

如果长度比例不当，可能误判为包含匹配。

**解决**：
- 设置合理的包含度阈值（默认0.8）
- 人工审核"包含匹配"的结果

### 2. 短文本问题

**问题**：人工标注文本过短，容易误匹配

**示例**：
```
人工: "必须" （2个字）
算法: "投标人必须满足以下要求"
```

**解决**：
- 人工标注时避免过短文本
- 最少包含完整的一句话

### 3. 重复内容

**问题**：同一要求在文档中多次出现

**解决**：
- 只标注一次（选择首次出现）
- 在备注中注明"适用全文"

## 📚 总结

### 层次化匹配的优势

✅ **处理粒度不一致**：支持粗粒度和细粒度匹配
✅ **提高匹配准确率**：减少因粒度问题导致的误判
✅ **提供详细信息**：区分完全匹配和包含匹配
✅ **灵活可配置**：可选择启用或禁用包含匹配

### 适用场景

| 场景 | 推荐模式 |
|------|----------|
| 算法输出段落，人工拆分标注 | 层次化匹配 ✅ |
| 算法和人工粒度一致 | 相似度匹配即可 |
| 需要严格验证 | 相似度匹配 + 人工审核 |
| 快速验证 | 层次化匹配 |
