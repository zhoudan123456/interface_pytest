## 📊 数据流向说明

**重要理解：所有文件都保存在服务器（你的电脑）上**

### 工作原理

```
┌─────────────────┐
│  团队成员A的电脑  │
└────────┬────────┘
         │ 1. 上传文件
         ↓
┌─────────────────┐
│   你的电脑       │  ← 所有处理和文件保存都在这里
│   (服务器)       │
│                 │
│ 📁 backend/     │
│    uploads/     │  ← 上传的文件
│    outputs/     │  ← 生成的报告
│                 │
│ 📁 test_data/   │
│    evaluation/  │
│    responses/   │  ← API提取结果
└────────┬────────┘
         │ 2. 返回结果/下载链接
         ↓
┌─────────────────┐
│  团队成员A的电脑  │  ← 只能看到和下载结果
└─────────────────┘
```

### 数据流向表

| 操作 | 文件流向 | 最终保存位置 |
|------|---------|------------|
| 上传文件 | 团队成员 → 你的电脑 | `backend/uploads/` |
| API提取（步骤1） | 你的电脑内部处理 | `test_data/evaluation/responses/` |
| LLM验证（步骤2） | 你的电脑内部处理 | `backend/outputs/` |
| 下载报告 | 你的电脑 → 团队成员 | 团队成员选择保存位置 |

### 文件保存位置详解

#### 步骤1（API提取）生成的响应文件

**保存在你的电脑上**：
```
test_data/evaluation/responses/
├── 项目名称_xxx_check_point_20260203_xxxxxx.json  ← 检查点数据
└── 项目名称_xxx_bid_info_20260203_xxxxxx.json      ← 招标信息
```

#### 步骤2（LLM验证）生成的报告文件

**保存在你的电脑上**：
```
backend/outputs/
└── 02aed497-019f-4d3e-951d-12fa75a0b155_validation_20260203_135234.md  ← 验证报告
```

### 实际使用场景举例

**场景**：团队成员小明使用这个工具

1. **小明**在他的电脑上打开浏览器，访问 `http://192.168.1.100:5175`
2. **小明**上传招标文件 PDF → 文件传到**你的电脑** (`backend/uploads/`)
3. **你的电脑**处理文件，生成检查点数据 → 保存在**你的电脑** (`test_data/evaluation/responses/`)
4. **小明**在浏览器看到结果 → 数据从**你的电脑**传回给小明
5. **小明**继续上传 Excel + JSON 进行验证 → 文件传到**你的电脑**
6. **你的电脑**调用AI生成验证报告 → 保存在**你的电脑** (`backend/outputs/`)
7. **小明**下载验证报告 → 文件从**你的电脑**传给小明的电脑

**结果**：
- ✅ 小明拿到了他需要的报告
- ✅ 所有原始文件和处理结果都在**你的电脑**上
- ✅ 小明可以选择下载报告到他的电脑，或者只在线查看

### 这意味着什么？

#### 优点：
✅ **集中管理**：所有数据在一台电脑上，方便备份和管理
✅ **数据安全**：数据不会散落在各个团队成员的电脑上
✅ **节省空间**：团队成员的电脑不需要存储大量文件

#### 需要注意：
⚠️ **依赖你的电脑**：你的电脑关机，其他人就无法使用
⚠️ **磁盘占用**：所有文件都占用你的电脑磁盘空间
⚠️ **隐私考虑**：你能看到所有用户上传的文件

### 团队成员的权限

#### 他们能做什么：
✅ 上传文件到你的电脑
✅ 查看处理进度
✅ 下载生成的报告
✅ 在线预览报告内容

#### 他们**不能**做什么：
❌ 直接访问你电脑上的文件系统
❌ 修改或删除服务器上的文件
❌ 看到其他用户上传的文件（除非功能支持）

### 类比说明

这就像使用百度网盘：
- 你是"网盘服务器"
- 团队成员是"用户"
- 文件都保存在你的电脑上，用户可以上传和下载

## 📋 阶段1：在你电脑上快速部署（5分钟）

### 步骤1：检查环境配置（2分钟）

打开命令行，进入项目目录：

```bash
cd D:\interface_pytest\interface_pytest
```

检查 `.env` 文件配置：

```bash
# 查看 .env 文件内容
type .env

# 应该看到：
ZHIPUAI_API_KEY=你的密钥
```

如果 `.env` 文件不存在：

```bash
# 复制示例文件
copy .env.example .env

# 编辑文件
notepad .env
```

填入你的智谱AI API密钥：
```env
ZHIPUAI_API_KEY=your.api.key.here
```

### 步骤2：启动服务（1分钟）

**方式1：使用启动脚本（推荐）**

```bash
start.bat
```

这会自动启动：
- Redis 服务（端口 6379）
- FastAPI 后端（端口 8001）
- Vue 3 前端（端口 5175）

**方式2：手动启动**

如果 `start.bat` 无法运行，可以手动启动三个服务：

```bash
# 窗口1 - 启动Redis
redis-server

# 窗口2 - 启动后端
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001 --reload

# 窗口3 - 启动前端
cd frontend
npm run dev
```

### 步骤3：获取局域网IP（30秒）

**Windows 查看本机IP**：

```bash
ipconfig
```

找到类似这样的输出：
```
无线局域网适配器 WLAN:
   IPv4 地址 . . . . . . . . . . . . : 192.168.1.100
                                                   ↑这就是你的IP
```

### 步骤4：配置Windows防火墙（重要！）

为了让团队成员能访问你电脑上的服务，需要配置防火墙开放端口。

**方式1：命令行配置（推荐，需要管理员权限）**

```bash
# 以管理员身份运行命令行，然后执行：

netsh advfirewall firewall add rule name="Bid Check Backend" dir=in action=allow protocol=TCP localport=8001
```

**方式2：图形界面配置**

1. 打开控制面板
2. 进入"Windows Defender 防火墙" → "高级设置"
3. 点击"入站规则" → "新建规则"
4. 选择"端口" → "TCP" → 特定本地端口：`5175, 8001`
5. 选择"允许连接"
6. 全部勾选（域、专用、公用）
7. 名称：`Bid Check Tool`
8. 完成

## ❓ 常见问题排查

### 问题1：团队成员无法访问

**症状**：你自己能访问，但同事打不开

**排查步骤**：

1. **检查防火墙**
   - 确认端口 5175 和 8001 已开放
   - 临时关闭防火墙测试（不推荐长期）

2. **检查服务监听地址**
   - 后端必须监听 `0.0.0.0`（不是 `127.0.0.1`）
   - 查看 `start.bat`，确认是：
   ```
   uvicorn app.main:app --host 0.0.0.0 --port 8001
   ```

3. **测试网络连通性**
   ```bash
   # 让同事 ping 你的IP
   ping 192.168.1.100

   # 如果不通，说明不在同一局域网
   ```

4. **测试端口**
   ```bash
   # 在同事电脑上浏览器访问：
   http://192.168.1.100:8001/api/v1/health
   ```

### 问题2：上传文件后没有响应

**症状**：上传文件后，界面一直加载

**原因**：LLM处理需要时间（16个检查点约需2-5分钟）

**解决方案**：
- 前端已设置10分钟超时，请耐心等待
- 查看后端日志，确认正在处理
- 如果超过10分钟，检查智谱AI API密钥是否正确

### 问题3：后端启动失败

**症状**：后端窗口一闪而过，或者报错

**常见原因及解决**：

1. **端口被占用**
   ```bash
   # 查看端口占用：
   netstat -ano | findstr :8001

   # 如果有进程占用，杀掉它：
   taskkill /PID 进程号 /F
   ```

2. **.env 文件配置错误**
   ```bash
   # 检查 .env 文件格式：
   ZHIPUAI_API_KEY=your.key.here  # 不要加引号
   ```

3. **依赖包未安装**
   ```bash
   cd backend
   pip install -r requirements.txt
   ```

4. **Redis 未启动**
   ```bash
   # 检查 Redis 是否运行：
   redis-cli ping
   # 应该返回：PONG
   ```

### 问题4：前端白屏或报错

**症状**：前端页面空白，控制台报错

**解决方案**：

```bash
# 1. 清除缓存重新安装
cd frontend
rmdir /S /Q node_modules
del package-lock.json
npm install

# 2. 检查API代理配置
# 查看 vite.config.ts，确认 proxy 配置正确

# 3. 重新启动
npm run dev
```

### 问题5：生成的报告文件找不到

**症状**：任务完成，但不知道报告在哪里

**查看位置**：

```bash
# 报告保存在：
backend/outputs/

# 文件命名格式：
{任务ID}_validation_{时间}.md

# 例如：
02aed497-019f-4d3e-951d-12fa75a0b155_validation_20260203_135234.md
```

创建清理脚本 `cleanup.bat`：

```batch
@echo off
echo 清理7天前的文件...

forfiles /p backend\outputs /m *.md /d -7 /c "cmd /c del @path"
forfiles /p backend\uploads /m *.* /d -7 /c "cmd /c del @path"

echo 清理完成！
pause
```

### 备份重要数据（每天）

创建备份脚本 `backup.bat`：

```batch
@echo off
set BACKUP_DIR=D:\bid-check-backup\%date:~0,4%%date:~5,2%%date:~8,2%
mkdir %BACKUP_DIR%

xcopy backend\outputs %BACKUP_DIR%\outputs\ /E /I /Y
xcopy backend\uploads %BACKUP_DIR%\uploads\ /E /I /Y

echo 备份完成：%BACKUP_DIR%
pause
```

### 迁移时机

建议在以下情况迁移到公司服务器：
- ✅ 团队使用频繁，需要稳定运行
- ✅ 你需要关闭自己的电脑

### 迁移步骤（30分钟）

#### 2.1 准备服务器

联系IT部门，要求：
- **操作系统**：Windows Server 2019+ 或 Ubuntu 22.04+
- **配置**：4核8G内存，100G磁盘
- **网络**：固定IP地址，例如：192.168.1.200
- **权限**：管理员权限或 sudo 权限

#### 2.2 在服务器上安装环境

**Windows Server**：

```powershell
# 1. 安装 Python 3.11+
# 下载安装包：https://www.python.org/downloads/

# 2. 安装 Node.js 20+
# 下载安装包：https://nodejs.org/

# 3. 安装 Redis
# 下载安装包：https://redis.io/download

# 4. 克隆代码
git clone <your-repo> C:\bid-check-tool
cd C:\bid-check-tool

# 5. 安装依赖
cd backend
pip install -r requirements.txt

cd ..\frontend
npm install

# 6. 配置环境变量
copy .env.example .env
notepad .env
# 填入 ZHIPUAI_API_KEY

# 7. 启动服务
start.bat
```

**Linux (Ubuntu)**：

```bash
# 1. 安装 Python 和 Node.js
sudo apt update
sudo apt install python3.11 python3-pip nodejs npm git redis-server

# 2. 克隆代码
sudo git clone <your-repo> /opt/bid-check-tool
cd /opt/bid-check-tool

# 3. 安装依赖
cd backend
pip3 install -r requirements.txt

cd ../frontend
npm install

# 4. 配置环境变量
sudo cp .env.example .env
sudo nano .env
# 填入 ZHIPUAI_API_KEY

# 5. 使用 Docker Compose（推荐）
sudo apt install docker docker-compose
sudo docker-compose up -d

# 6. 设置开机自启
sudo systemctl enable docker
sudo systemctl enable redis-server
```

#### 2.3 更新前端配置

修改前端API地址，指向服务器IP：

```typescript
// frontend/vite.config.ts
export default defineConfig({
  server: {
    port: 5175,
    host: '0.0.0.0',  // 允许外部访问
    proxy: {
      '/api': {
        target: 'http://192.168.1.200:8001',  // 服务器IP
        changeOrigin: true
      }
    }
  }
})
```

#### 2.4 重新构建前端（生产环境）

```bash
cd frontend
npm run build  # 构建生产版本
```

构建完成后，静态文件在 `frontend/dist/` 目录。

可以使用 Nginx 提供静态文件服务：

```nginx
# nginx.conf
server {
    listen 80;
    server_name 192.168.1.200;

    # 前端静态文件
    location / {
        root /opt/bid-check-tool/frontend/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端API
    location /api {
        proxy_pass http://localhost:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # WebSocket
    location /ws {
        proxy_pass http://localhost:8001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

#### 2.5 配置服务器防火墙

**Linux**：
